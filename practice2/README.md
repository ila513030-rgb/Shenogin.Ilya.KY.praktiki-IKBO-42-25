Инструмент анализа зависимостей JavaScript-пакетов (npm) на Python 3.
Это **отдельная** работа: код первой практики находится в корне
основного репозитория. В этой работе используется **CLI**, как
предписано методичкой. Внешние библиотеки и npm для получения
зависимостей не используются (только стандартная библиотека Python).

## Этапы

1. **CLI и конфигурация.** Параметры командной строки, вывод
   ключ–значение и обработка ошибок.
2. **Прямые зависимости npm.** Данные берутся из официального API
   `https://registry.npmjs.org/<package>/latest`. Используется поле
   `dependencies` из метаданных версии `latest`.
3. **Полный граф.** Итеративный DFS со стеком и множеством посещённых
   пакетов, отсечение пакетов по подстроке, обработка циклов и
   тестовый режим с графом в JSON.

**Этапы 4–5 не выполнялись.** Изображение графа не создаётся:
параметр `--output` только конфигурируется и проверяется.

## Параметры

| Ключ | Назначение |
| --- | --- |
| `--package` | Корневой пакет (обязательный) |
| `--repository` | `https://registry.npmjs.org` или путь к JSON |
| `--test-mode` | Переключатель тестового режима |
| `--output` | Имя будущего PNG, по умолчанию `graph.png` |
| `--filter` | Подстрока для исключения узлов графа |

Для тестового режима имена пакетов — **одна заглавная латинская
буква A–Z**. JSON представляет отображение имени пакета на список
его прямых зависимостей. Каждый упомянутый пакет должен быть описан
в файле, в том числе листовые узлы с пустым списком.

## Запуск из корня общего репозитория

Windows:

```powershell
python -m practice2.src.main --package A --repository practice2/tests/data/chain.json --test-mode
```

Linux:

```bash
python3 -m practice2.src.main --package A --repository practice2/tests/data/cycle.json --test-mode
```

Либо `practice2/run.bat ...` / `sh practice2/run.sh ...`.
Действительный npm-пакет:

```bash
python -m practice2.src.main --package is-number --repository https://registry.npmjs.org
```

Запуск требует интернет-соединения. Используется npm-тег `latest`
для каждого пакета: **разрешение диапазонов semver** зависимостей не
реализовано (упрощение первых трёх этапов); полный граф может не
совпадать с результатом установки конкретной версии npm.

## Проверка всех этапов

```powershell
python -m unittest discover -s practice2/tests -v
```

Примеры сценариев:

- `chain.json`: ветвление и транзитивная зависимость D.
- `cycle.json`: A → B → C → A, нет бесконечного цикла.
- `filter.json` с `--filter B`: исключение B и его ветки,
  но D остаётся достижим через C.
- `empty.json`: пакет без зависимостей.
- `invalid.json`: ошибка из-за неописанного пакета.
- неправильный путь, `--output bad.txt`, неверный URL:
  явные сообщения об ошибках.

### Где что находится

- `src/config.py` — проверка параметров;
- `src/repository.py` — npm API и загрузка тестовых графов;
- `src/graph.py` — DFS без рекурсии;
- `src/main.py` — запуск и текстовый вывод;
- `tests/test_graph.py` — автоматические тесты.

Программа выводит граф в текстовом виде (список смежности).
Это не визуализация изображения; она относится к пятому этапу.
